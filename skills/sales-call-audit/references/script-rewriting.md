# Script rewriting

Rewrite the requested scope: a single response, a stage, or a full call. Use the supplied trainer profile for method and delivery traits. Generated scripts are original suggested wording, never attributed quotations or claims about what the trainer would certainly say.

## Establish the inputs

Infer what is supported by the call: product, buyer, lead source, prior contact/prework, rep role, desired next step, confirmed problem, and outstanding objections. Load current approved offer facts when supplied. Ask only for material missing facts. If a benefit, proof point, price, policy, or delivery capability is unknown, use a clearly labeled placeholder or omit it. Do not make a hypothetical script sound ready to use while hiding critical placeholders.

Separate adherence from redesign. If the organization has an approved script, identify the gap between the call and that script. A requested rewrite can improve the draft, but is not permission to replace a live process. Explain when a source script assumes prior education or a setter's discovery that this call lacks.

## Write the sequence

- Opening: identify the rep/company/reason, handle applicable disclosure, establish time and the next step.
- Discovery: establish current state, desired state, obstacle, attempted solution, and a concrete example. Recap and get confirmation. Ask follow-ups because an answer needs clarification, not to fill a template.
- Transition: ask permission to explain the relevant solution once the problem is confirmed.
- Offer: buyer problem → verified capability → relevant assurance → buyer benefit → confirmation. Tie the purchase to what changes for the buyer; don't list every module or feature. Do not invent three problems merely to fill three pillars.
- Ask: ask for the stage-appropriate decision, state required terms clearly, then `[wait]`. Do not write the buyer's agreement as though it is inevitable.
- Concern: acknowledge, clarify the unresolved issue, address only what can be supported, check the response, and ask for the appropriate next step. Distinguish initial value/concern triage from later loops.
- Follow-up: if needed and welcome, agree who, when, what must happen beforehand, and what the next conversation will decide.
- After a sale: confirm actual payment status, explain onboarding and next actions, then ask for a referral when appropriate. A payment promise is not receipt.

## Make it usable

Give ready-to-say dialogue with `[wait]` at decisions and brief `If ...` branches. Keep instructions outside the spoken text. Use ordinary language and contractions. Read it as speech: remove throat-clearing, repeated questions, jargon, and claims that would require a fact the user hasn't supplied. Keep a full script modular rather than a monologue. Add a short explanation of the important changes; do not annotate every line.

For practice: frame the specific skill, model a correct response, let the participant copy/attempt, correct immediately, repeat the corrected behavior, recap. Change the buyer's reply once the first version is executed cleanly so the rep learns the decision, not just a memorized sentence. Never default the uploader into the rep role.
